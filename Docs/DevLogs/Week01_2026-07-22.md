## 💭 本周思考与复盘

### 祖传代码的核心问题

| 问题类型           | 具体表现                                               |
| -------------- | -------------------------------------------------- |
| **脚本粒度过细**     | 功能零散、不可复用，甚至有脚本专门负责跳转到某个特定场景（如 `Back.ToSellect()`） |
| **Manager 泛滥** | 单例模式使用过度，缺乏精简意识，导致幽灵单例频发，被迫大量使用 `Find` 补救          |
| **分类维度错误**     | 子弹按“谁发射的”分类，而非按“子弹种类”分类，导致逻辑重复                     |

### 教训与原则

> **核心教训：不能按场景分脚本，耦合性太差且不可复用。**  
> 根源是早期能力不足，脚本功能粒度过细，缺乏抽象意识。

**后续开发应警惕：**

- 单例模式不是万能药，控制使用频率和范围
    
- 功能应按**职责**划分，而非按**场景**或**触发者**
    
- 一个脚本只做一件事，但要确保那件事是**有复用价值**的

\##🧠 设计思路



这次整理的核心原则是 “按功能模块划分，而非按资源类型划分” 。



之前的结构（如 mine/、Gems/、map/）是随着开发随手建的，没有统一的规划，导致：



一个功能（比如“敌人”）的脚本、预制体、数据分散在多个文件夹里



第三方插件（A\*寻路）和我的代码混在一起，分不清哪些是外部依赖



新功能不知道往哪放，最终导致根目录越来越乱



这次整理后，所有内容按“功能模块”聚合，同一个模块的脚本、预制体、数据放在一起；第三方插件统一隔离到 \_ThirdParty 目录下。这样以后添加新功能时，可以明确知道该放在哪个位置。



\##🛠️ 具体实现



统一命名规范：将文件夹和文件统一为英文命名（如 Enemy 取代 敌人），使用 PascalCase 或 camelCase 规范。



目录分层：



\_Project/：存放所有自主开发的代码和资源



\_ThirdParty/：存放所有外部插件（如 A\* Pathfinding Project）



\_Sandbox/：存放临时测试场景和实验性脚本



模块化分类：在 \_Project/Scripts/ 下按功能划分文件夹（如 Combat/、Gems/、Inventory/、UI/、Utilities/），每个模块只包含该功能的脚本。



清理无效文件：使用 Unity 的 Find References in Scene 和 Select Dependencies 功能，排查并删除未被引用的脚本和资源。

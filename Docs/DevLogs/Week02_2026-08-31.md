## 宝石重构架构

分成四块：

1. **UI 层**：显示数据，接收点击，调用交互器
    
2. **交互层**：转发 UI 指令到数据层（几乎没有业务逻辑）（）
    
3. **数据层**：`GemManager` 维护宝石库存和装备状态，提供增删改查和装备/卸下方法，自己检查合法性，修改后通知 `SaveManager` 保存
    
4. **战斗装载层**：进入战斗时一次性读取装备列表，生成视觉效果，不持有数据

**原有问题：**

- `GameObject.Find` 滥用，依赖名称字符串，改个名就崩
    
- 数据与 UI 混杂（`Slot` 脚本同时处理显示、数据修改、装备逻辑、UI查找）
    
- 跨场景数据传递用字符串列表（`Ku.nameList`）
    
- 单例不统一，多处手动调用 `Awake()` 补救初始化顺序
    
- 两个页面切换器（`TownCanvasManager` 和 `UIManager`）做同一件事，职责重叠
    

**重构后的架构：**

- **SaveManager**：唯一读写文件的地方，管理 `GameSaveData`（含三层数据 + 设置偏好）
    
- **GameManager**：全局单例 + `DontDestroyOnLoad`，负责场景切换和初始化流程编排
    
- **PageRouter**（原 `UIManager`）：负责页面切换，不处理业务逻辑
    
- **SettingManager**：全局单例，从 `SaveData.crossData` 读写设置，不自己管文件
    
- **GemManager**（计划中）：管理宝石库存和装备配置，提供增删改查接口
    
- **EquipmentInteractor**（计划中）：纯转发 UI 指令到数据层
    
- **Slot**（计划重构）：纯显示，只触发点击事件，不修改数据

## 场景三（战斗场景）完整架构图

|层级|模块|职责|
|---|---|---|
|**流程控制层**|`GameManager`（已有）|全局单例。负责：场景切换（村庄→场景2→场景3）、胜负判定后的场景跳转、保存游戏。**不负责战斗内的具体逻辑**|
|**流程控制层**|`LevelManager`（新增）|战斗场景的局域协调者。负责：监听`GameManager`的“关卡开始”事件 → 协调`MapLoader`加载地图、协调`WaveSpawner`开始生成、协调`GemWeapon`激活宝石效果、监听波次结束/玩家死亡/倒计时结束 → 向`GameManager`上报胜负结果。**所有战斗内模块只跟LevelManager对话，不直接引用GameManager**|
|**地图层**|`MapLoader`（重构）|接收`LevelManager`传来的地图ID → 从映射表（ID→预制体资源路径）找到对应预制体 → 实例化到场景中的“地图挂载点”下。地图预制体内部自带：`MapInfo`组件（暴露生成点列表）、碰撞体、视觉装饰。切换关卡时销毁旧地图、加载新地图|
|**生成层**|`WaveConfig`（新增，ScriptableObject）|数据资产。描述“某一天/某一关的波次结构”：包含多个波次，每个波次包含：持续时间、敌人类型ID列表、每个敌人的数量/生成间隔。**只存数据，不存逻辑**|
|**生成层**|`WaveSpawner`（新增）|挂在“地图挂载点”下或独立节点。接收`LevelManager`的“开始生成”指令 → 读取当前关卡的`WaveConfig` → 按时间线驱动波次 → 每个生成周期向`EnemyPool`请求敌人实例（传入敌人类型ID和生成位置）→ 从`MapInfo`获取随机生成点。**不关心敌人具体是什么，只关心ID和位置**|
|**敌人层**|`EnemyRepository`（新增）|全局缓存（存在于场景3生命周期）。关卡开始时接收`LevelManager`传来的“本关所有登场敌人ID列表” → 从`GameConfig`取对应Prefab → 建立并维护`Dictionary<string, GameObject>`。供`EnemyPool`按需取用。**职责单一：只负责“ID→Prefab”的映射和缓存**|
|**敌人层**|`EnemyPool`（新增）|对象池。接收`WaveSpawner`的“生成请求（敌人类型ID，位置）” → 检查池中是否有空闲实例 → 有则激活并重置状态，无则从`EnemyRepository`取Prefab实例化 → 返回实例给`WaveSpawner` → 敌人死亡时回收回池子（而非销毁）。**负责实例的生命周期管理，不关心波次逻辑**|
|**敌人层**|`EnemyBase`（已有，重构）|敌人的行为容器。生成时由`EnemyPool`调用`EnemyBehaviorFactory`为其装配策略列表（移动策略、攻击策略、死亡策略等）。策略数据从`GameConfig`读取。**自身只负责调用策略的生命周期方法**|
|**能力层（策略系统）**|`IBehavior`（新增，接口）|定义策略的生命周期：`OnEnable()`、`OnUpdate()`、`OnHit()`、`OnDisable()`|
|**能力层（策略系统）**|`BehaviorContainer`（新增，组件）|挂载在需要策略的对象（宝石、子弹、敌人）上。内部维护`List<IBehavior>`。暴露`AddBehavior()`和`RemoveBehavior()`方法。在自身的`Update()`中遍历调用所有策略的`OnUpdate()`，碰撞时调用`OnHit()`。**策略之间完全独立，互不知晓**|
|**能力层（策略系统）**|`BehaviorFactory`（新增）|接收一个“上下文”（宝石ID / 子弹类型 / 敌人类型ID） → 从`GameConfig`读取该类型对应的策略ID列表 → 实例化对应的策略对象 → 返回`List<IBehavior>`。**拼积木的地方**|
|**能力层（策略系统）**|`GemEffectConfig`（新增，ScriptableObject）|数据资产。定义每个宝石ID对应的：策略ID列表（如“伤害策略+灼烧策略”）、每个策略的参数（伤害值、持续时间等）。供`BehaviorFactory`读取|
|**能力层（策略系统）**|`BulletConfig`（新增，ScriptableObject）|数据资产。定义每种子弹类型对应的策略ID列表和参数。供`BehaviorFactory`读取|
|**能力层（策略系统）**|`EnemyConfig`（新增，ScriptableObject）|数据资产。定义每种敌人类型ID对应的策略ID列表和参数（移动策略、攻击策略、死亡掉落策略等）。供`BehaviorFactory`读取|
|**装备层**|`EquipmentManager`（新增）|存在于场景3。关卡开始时从`GemManager`获取当前装备的宝石ID列表（`List<string>`长度为4）→ 从`GameConfig`取对应宝石的图标Prefab → 实例化到四个装备槽位的UI上。**只负责显示，不负责效果激活**|
|**装备层**|`GemWeapon`（新增，武器子类）|存在于场景3，挂在玩家武器上。关卡开始时调用`BehaviorFactory`，传入“当前装备的所有宝石ID列表” → 工厂从`GemEffectConfig`读取策略列表 → 装配到`BehaviorContainer`中。射击时生成的子弹携带这些策略的副本（子弹生成时再调用一次工厂，传入宝石ID）。**武器本身只是一个发射器和策略容器**|
|**装备层**|`Bullet`（新增，子弹组件）|子弹本体，挂载`BehaviorContainer`。生成时由`GemWeapon`传入策略列表 → 飞行过程中策略自行运作（如追踪、分裂等） → 命中时触发策略的`OnHit()`。**子弹自身不知道有什么效果，只是容器的载体**|
|**数据层**|`GemManager`（已有）|宝石库存查询/增删、装备槽位查询/装备/卸下。对接`SaveManager`。供`EquipmentManager`和`GemWeapon`读取|
|**数据层**|`SaveManager`（已有）|读写JSON存档。存储：宝石库存、已装备宝石ID列表（4个槽位）、当前天数/关卡进度等|
|**配置层**|`GameConfig`（已有，扩充）|统一配置入口。提供：宝石ID→图标/名称/描述/Prefab、敌人类型ID→Prefab/基础数据、策略ID→策略类型映射、子弹类型ID→Prefab。**所有工厂和仓库都从这里取数据**|

### 2.4 战斗场景架构设计（D5-D7）

#### 整体分层架构

| 层级 | 模块 | 职责 |
|------|------|------|
| **流程控制层** | `GameManager`（已有） | 全局单例，负责场景切换、胜负判定跳转、存档保存 |
| **流程控制层** | `LevelManager`（新增） | 战斗场景局域协调者，协调地图加载、波次生成、宝石效果激活、胜负上报 |
| **地图层** | `MapLoader`（重构） | 接收地图ID → 加载对应预制体 → 挂载到场景挂载点 |
| **生成层** | `WaveConfig`（新增，SO） | 描述某天/某关的波次结构（持续时间、敌人类型、数量、间隔） |
| **生成层** | `WaveSpawner`（新增） | 读取 `WaveConfig`，按时间线驱动波次，向 `EnemyPool` 请求敌人 |
| **敌人层** | `EnemyRepository`（新增） | ID → Prefab 映射缓存，关卡开始时由 `LevelManager` 注入 |
| **敌人层** | `EnemyPool`（新增） | 对象池管理敌人实例的生命周期（生成/回收） |
| **敌人层** | `EnemyBase`（重构） | 行为容器，通过工厂装配策略列表，调用策略生命周期 |
| **能力层（策略系统）** | `IBehavior`（新增） | 策略生命周期接口：`OnEnable/Update/Hit/Disable` |
| **能力层（策略系统）** | `BehaviorContainer`（新增） | 挂载在宝石/子弹/敌人上，遍历调用策略方法 |
| **能力层（策略系统）** | `BehaviorFactory`（新增） | 根据上下文（宝石ID/敌人ID/子弹类型）装配策略列表 |
| **能力层（策略系统）** | `GemEffectConfig` / `BulletConfig` / `EnemyConfig`（新增，SO） | 各类型对应的策略ID列表与参数配置 |
| **装备层** | `EquipmentManager`（新增） | 在战斗场景显示已装备宝石的UI图标 |
| **装备层** | `GemWeapon`（新增） | 玩家武器，装配宝石策略，射击时生成携带策略副本的子弹 |
| **装备层** | `Bullet`（新增） | 子弹本体，挂载 `BehaviorContainer`，飞行与命中触发策略 |
| **数据层** | `GemManager`（已有） | 宝石库存与装备槽位查询接口，供 `EquipmentManager` / `GemWeapon` 读取 |
| **数据层** | `SaveManager`（已有） | JSON 文件读写，存储宝石库存、装备列表、关卡进度 |
| **配置层** | `GameConfig`（已有，扩充） | 统一配置入口：宝石/敌人/子弹/策略ID映射 |

### 2.5 策略模式 vs 状态机 技术选型（D7）

| 模式 | 适用场景 | 本项目中应用 |
|------|----------|-------------|
| **状态机** | 切换一套“规则包”（属性 + 可用行为 + 约束条件） | **敌人**——不同状态下属性/行为/约束差异大 |
| **策略模式** | 切换一个“行为配方”（具体怎么做） | **宝石效果**——纯行为组合，无内部状态切换；<br>**子弹**——行为单一且正交 |

## 四、本周思考与复盘

### 4.1 祖传代码耦合问题识别

现有依赖链存在过度耦合：

```
KuManager ←→ Inventory
    ↓
EquipmentManagerInBag ←→ Inventory
    ↓
LevelController ←→ KuManager + EquipmentManagerInBag
```

**改进方向**：减少 Manager 之间的直接引用，通过事件系统或中介者模式解耦。

### 4.2 架构原则沉淀

- 数据层不持有 UI 引用，UI 层通过交互层间接操作数据
- 跨场景数据传递走 `SaveManager`，不通过静态列表或 `DontDestroyOnLoad` 滥用
- 每个 Manager 职责单一，避免“上帝对象”
- 策略之间完全独立，互不知晓，通过 `BehaviorContainer` 组合执行

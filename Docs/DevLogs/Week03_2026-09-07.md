d1 
**Day 1：基础设施层重构 - 开发日志**

**工作目标**：为战斗场景重构搭建底层架构，确保数据驱动与模块解耦。

**1. 配置系统重构**  
将原本零散的配置整合为统一数据层，新增 `BehaviorConfig` 与 `BehaviorEntry` 数据结构。制定了宝石、子弹、敌人各自拥有独立策略列表的配置规范，明确区分“实体数据”与“行为逻辑”，为后续工厂模式奠定基础。解决了命名空间与程序集引用冲突导致的编译错误。

**2. 策略系统骨架搭建**  
设计 `IBehavior` 生命周期接口（Initialize、Update、Hit、Dispose），实现 `BehaviorContainer` 作为策略挂载载体。确立“策略间互相无依赖，由容器统一驱动”的结构原则，为宝石效果与子弹行为的模块化组合做好准备。

**3. 对象池实现**  
将 `EnemyRepository` 合并进 `EnemyPool`，形成“Prefab缓存 + 对象池 + 策略装配”的三合一模块。采用全局单例模式（`DontDestroyOnLoad`）实现跨关卡复用，避免频繁 Instantiate/Destroy 带来的性能开销，保证战斗流畅度。

**4. 决策与调整**

- 采纳“优化掉 EnemyRepository”的建议，简化调用链为 WaveSpawner → EnemyPool → GameConfig
    
- 确认策略为可选项：普通敌人仅使用状态机，特殊敌人附加策略组合
    

**5. 产出文件**  
`GameEnums.cs`、`GameConfig.cs`、`BehaviorConfig.cs`、`GemConfig.cs`、`ProjectileConfig.cs`、`EnemyConfig.cs`、`DeviceConfig.cs`、`BehaviorEntry.cs`、`IBehavior.cs`、`BehaviorContainer.cs`、`BehaviorFactory.cs`、`EnemyPool.cs`、`EnemyBase.cs`

**Day 2：生成层与地图层构建 - 开发日志**

**工作目标**：建立波次生成系统与地图动态加载机制，打通“关卡配置 → 敌人生成”的完整链路。

**1. 波次数据资产定义**  
创建 `WaveConfig` ScriptableObject，将波次配置从代码中剥离为纯数据资产。每波支持多种敌人混合生成（`SpawnEntry`），通过 `duration`（波次时长）和 `spawnInterval`（个体间隔）双维度控制生成节奏，为策划提供灵活调参空间。

**2. 波次生成器实现**  
实现 `WaveSpawner` 核心逻辑，按时间线驱动波次推进。采用“独立条目计时器”方案处理同波次内多类型敌人同时生成的需求，支持动态增删生成条目。暴露 `StartSpawning/StopSpawning` 接口供协调层调用，与敌人生成位置完全解耦。

**3. 地图动态加载重构**  
将地图从“场景内预置”改为“预制体动态加载”。实现 `MapLoader` 支持按 ID 从字典查表实例化地图，切换关卡时自动销毁旧地图。采用 `Collider2D/SpriteRenderer` 自动计算地图边界，无需手动标记生成点。

**4. 随机生成位置算法**  
弃用固定生成点方案，改为“地图边缘随机 + 玩家安全距离”算法。敌人始终从地图四周边界生成，且与玩家保持 5 单位以上的安全距离，使战局分布更自然。

**5. 关卡协调层搭建**  
新增 `LevelManager` 作为场景3的局域协调者，统一管理生存倒计时、地图加载、波次启动、胜负判定。将生存倒计时（3分钟）与波次推进计时分离，确保两者互不干扰。

**6. 决策与调整**

- 确认计时分离原则：LevelManager 管生存倒计时，WaveSpawner 管波次切换
    
- 移除 `MapInfo` 组件，简化地图结构为“视觉 + 碰撞体”
    
- 采纳“边缘随机生成”替代固定生成点方案
    

**7. 产出文件**  
`WaveConfig.cs`、`WaveSpawner.cs`、`MapLoader.cs`、`LevelManager.cs`、`PlayerHealth.cs`（简化版）
